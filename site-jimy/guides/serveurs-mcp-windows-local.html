Comment Créer et Connecter des Serveurs MCP sur Windows pour son Agent IA

Mis à jour le 17 octobre 2026 · Par Jimmyjoe13 · Temps de lecture : 8 min

Le Model Context Protocol (MCP) est en passe de devenir le standard industriel universel pour interconnecter les modèles d'intelligence artificielle avec les données, outils et environnements d'exécution locaux. 01. Qu'est-ce que le protocole MCP et pourquoi sur Windows ?

Historiquement, pour donner des capacités d'action à un grand modèle de langage (LLM), chaque plateforme imposait son format propriétaire : les GPT Actions d'OpenAI, les Plugins ou les appels de fonctions sur-mesure. Dès qu'un développeur changeait de modèle ou de client, l'ensemble des intégrations devait être réécrit.

Initié par Anthropic puis rapidement adopté par l'ensemble de la communauté open source, le Model Context Protocol (MCP) joue pour l'IA le même rôle que le protocole LSP (Language Server Protocol) a joué pour les éditeurs de code comme VS Code :

  • Découplage total : Le client (votre agent IA comme Jimy) n'a pas besoin de connaître la logique interne des outils.
  • Standardisation JSON-RPC 2.0 : Tout passe par des messages structurés exposant des Tools (outils exécutables), des Resources (données lisibles) et des Prompts (modèles de tâches).
  • 100% Local et Privé : Les serveurs MCP s'exécutent en local sur votre machine Windows. Aucune donnée ne transite par un serveur cloud intermédiaire avant que vous ne l'autorisiez.

02. Anatomie technique : Le transport stdio sous Windows

Le protocole MCP propose deux modes de communication principaux :

  1. stdio (Standard Input / Output) : Le client lance le processus du serveur MCP en sous-processus et communique via les flux d'entrée et de sortie standard (stdin et stdout). C'est le mode le plus simple, le plus rapide et le plus sécurisé pour une exécution de bureau locale.
  2. SSE (Server-Sent Events) via HTTP : Utilisé lorsque le serveur tourne sur une machine distante ou dans un conteneur réseau.

Spécificité Windows : Sous Windows, les processus fils lancés via PowerShell ou cmd doivent gérer correctement les fins de ligne (\r\n vs \n) et l'encodage UTF-8. Assurez-vous que votre environnement Python ou Node.js est configuré avec l'encodage UTF-8 activé par défaut.

03. Tutoriel : Brancher un serveur MCP officiel (Filesystem & SQLite)

L'écosystème open source fournit déjà des dizaines de serveurs prêts à l'emploi. Prenons l'exemple du serveur officiel Filesystem, qui permet à l'agent de naviguer, lire et écrire dans des répertoires sécurisés sans compromettre le reste de votre disque dur.

Exemple de configuration JSON

Dans votre client agentique (ou dans le fichier de configuration des serveurs MCP de Jimy), la déclaration d'un serveur stdio ressemble à ceci :

mcp_config.json JSON 
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-filesystem",
        "C:\\Users\\MonNom\\Documents\\ProjetsIA",
        "C:\\Users\\MonNom\\Downloads"
      ]
    },
    "sqlite": {
      "command": "uvx",
      "args": [
        "mcp-server-sqlite",
        "--db-path",
        "C:\\Users\\MonNom\\Databases\\ventes_2026.db"
      ]
    }
  }
}

Astuce performance Windows : Préférez l'utilisation de uvx (fourni par l'outil ultra-rapide uv d'Astral) plutôt que des environnements virtuels Python lourds. uvx télécharge et exécute les serveurs MCP Python en quelques millisecondes dans un bac à sable isolé.

04. Créer son propre serveur MCP en Python avec FastMCP

Créer un serveur MCP personnalisé ne prend que quelques lignes de code grâce à la bibliothèque officielle FastMCP. Voici un exemple complet permettant à votre agent d'interroger les informations système de votre PC Windows (état de la batterie, mémoire vive libre, ou lancement d'une commande PowerShell sécurisée) :

windows_system_server.py Python 3.11+ 
# Installation : pip install "mcp[cli]" psutil
import psutil
from mcp.server.fastmcp import FastMCP

# Initialisation du serveur MCP nommé "WindowsSystem"
mcp = FastMCP("WindowsSystem")

@mcp.tool()
def get_system_health() -> str:
    """Renvoie les métriques matérielles actuelles de la machine Windows : CPU, RAM et batterie."""
    cpu_percent = psutil.cpu_percent(interval=1)
    ram = psutil.virtual_memory()
    battery = psutil.sensors_battery()
    
    battery_info = f"{battery.percent}% ({'En charge' if battery.power_plugged else 'Sur batterie'})" if battery else "Fixe / Sans batterie"
    
    return (
        f"Diagnostic Windows :\n"
        f"• Utilisation CPU : {cpu_percent}%\n"
        f"• RAM disponible : {ram.available // (1024 * 1024)} Mo sur {ram.total // (1024 * 1024)} Mo\n"
        f"• Batterie : {battery_info}"
    )

@mcp.tool()
def list_active_windows_services() -> list[str]:
    """Liste les services Windows en cours d'exécution liés aux bases de données ou aux serveurs locaux."""
    monitored = ["postgresql", "redis", "docker", "ollama"]
    found = []
    for proc in psutil.process_iter(['name']):
        name = proc.info['name'].lower()
        if any(m in name for m in monitored):
            found.append(name)
    return list(set(found))

if __name__ == "__main__":
    # Démarre le transport stdio pour écouter les requêtes de Jimy
    mcp.run(transport="stdio")

Pour tester votre serveur localement sous Windows dans PowerShell avant de le brancher à Jimy, utilisez l'inspecteur MCP officiel :

Console PowerShell CLI 
npx @modelcontextprotocol/inspector python windows_system_server.py

05. Créer un serveur MCP en Node.js / TypeScript

Si votre écosystème est basé sur JavaScript ou TypeScript, le SDK officiel @modelcontextprotocol/sdk permet de concevoir des outils en quelques minutes :

server.js Node.js (ESM) 
import { Server } from "@modelcontextprotocol/sdk/server/index.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { CallToolRequestSchema, ListToolsRequestSchema } from "@modelcontextprotocol/sdk/types.js";

const server = new Server(
  { name: "outils-projets", version: "1.0.0" },
  { capabilities: { tools: {} } }
);

// 1. Déclarer la liste des outils disponibles
server.setRequestHandler(ListToolsRequestSchema, async () => {
  return {
    tools: [
      {
        name: "calculer_tva",
        description: "Calcule le montant de la TVA et le total TTC pour un montant HT donné",
        inputSchema: {
          type: "object",
          properties: {
            montantHT: { type: "number", description: "Montant hors taxes en euros" },
            taux: { type: "number", description: "Taux de TVA en pourcentage (ex: 20)", default: 20 }
          },
          required: ["montantHT"]
        }
      }
    ]
  };
});

// 2. Exécuter l'outil quand l'agent IA le demande
server.setRequestHandler(CallToolRequestSchema, async (request) => {
  if (request.params.name === "calculer_tva") {
    const ht = request.params.arguments.montantHT;
    const taux = request.params.arguments.taux || 20;
    const tva = ht * (taux / 100);
    const ttc = ht + tva;
    return {
      content: [
        {
          type: "text",
          text: `Résultat : HT = ${ht.toFixed(2)} €, TVA (${taux}%) = ${tva.toFixed(2)} €, Total TTC = ${ttc.toFixed(2)} €`
        }
      ]
    };
  }
  throw new Error("Outil inconnu");
});

// Connexion sur les flux standards Windows
const transport = new StdioServerTransport();
await server.connect(transport);

06. Sécurité sur Windows : Garde-fous et autorisations

Donner des outils d'exécution à une intelligence artificielle sur son système d'exploitation principal exige une politique de sécurité sans compromis. Contrairement aux modèles cloud fermés qui exécutent des requêtes dans votre dos, Jimy applique une politique stricte de consentement :

  • Cartes d'approbation visuelles : Dès qu'un serveur MCP sollicite une action à impact persistant (création ou suppression de fichier, exécution de binaire, envoi de données externes), Jimy affiche une carte d'autorisation interactive sur votre bureau.
  • Isolation des répertoires : Ne donnez accès à un serveur MCP de système de fichiers qu'aux sous-dossiers stricts dont vous avez besoin (ex: votre dossier de projet ou votre coffre de notes). Ne montez jamais la racine C:\ directement.
  • Gestion des secrets : Les clés API et identifiants doivent être injectés via des variables d'environnement locales (process.env ou os.environ), jamais codés en dur dans vos scripts ou vos prompts.

07. Questions fréquentes (FAQ) sur les serveurs MCP

Quelle est la différence entre une API REST et un serveur MCP ?

Une API REST impose des formats d'URL et des schémas JSON hétérogènes que le modèle de langage doit interpréter au cas par cas. Le protocole MCP standardise l'auto-découverte (tools/list), la description des types en JSON-Schema et la gestion des flux conversationnels. Le LLM sait immédiatement comment utiliser n'importe quel serveur MCP sans code d'adaptation spécifique.

Les serveurs MCP fonctionnent-ils avec tous les LLM ?

Oui. Même si le protocole a été initié par l'écosystème Anthropic, il est agnostique du modèle sous-jacent. Que vous utilisiez Claude 3.5 Sonnet, GPT-4o, DeepSeek V3 ou un modèle open source local exécuté sur votre machine via Ollama ou LM Studio, Jimy traduit les appels de fonction MCP vers l'API de votre modèle de façon transparente.

L'exécution de plusieurs serveurs MCP ralentit-elle mon PC Windows ?

Non. En mode stdio, les serveurs MCP ne tournent que sous forme de processus légers en attente d'événements. Leur empreinte mémoire est généralement inférieure à 30 Mo de RAM, et ils ne consomment des cycles CPU que lorsqu'une commande est explicitement demandée.
